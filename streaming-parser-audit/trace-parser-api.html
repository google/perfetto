TraceParser: parser-only entrypoint

TraceParser accepts TraceBlobView through Parse and finishes through NotifyEndOfFile. It builds no SQL engine. TraceProcessor preserves parsing, retained storage and query support. This prototype still composes the shared internal TraceProcessorStorageImpl parsing core; naming and deeper extraction remain unfinished.

Public configuration contains parsing/sorting options only. Retention decisions and frontier batching belong to the implementation. There is no Flush method, legacy byte-array overload or public storage access.

Hand-written per-table sinks

TraceParserSinks contains optional borrowed pointers for SliceSink, ArgSink, SchedSink, ThreadStateSink and CounterSink. Each interface receives OnInsert(id, typed Row), named typed update callbacks, storage and completion frontier callbacks, reset and EOF. Return Status to propagate a consumer failure; errors remain sticky. Sinks must outlive the parser. Copy borrowed string views inside callbacks; IDs identify strings within the parser lifetime.

TraceParserSinks sinks;
sinks.counters = &my_counter_sink;
auto parser = TraceParser::CreateInstance(TraceParserConfig{}, sinks);
parser->Parse(blob_view);
parser->NotifyEndOfFile();
TableStorage and late updates
SliceActive stack caches values. Historical storage advances despite open parents. Deferred translations can patch old IDs.
ArgsImmutable complete arg sets advance storage and completion. Distinct arg-set hashes and strings remain retained.
SchedProto ftrace caches open CPU timestamps; storage advances past stalled CPUs. Completion follows open rows.
Thread stateProto ftrace caches current thread state; late blocked reasons keep completion conservative.
CounterAll value arrays omitted. Storage advances every 1,024 rows. Deferred track IDs and backward-looking GPU values still patch evicted IDs; completion stays zero.

Limits of this sketch

These are five public table interfaces, not a complete relational export: track, process, thread, flow and metadata sinks still need public interfaces. Internal generated sink machinery covers other tables. JSON generic scheduling retains needed history. Parser dictionaries, distinct strings, pending resolutions and the normal sorter can grow; arbitrary traces do not have a bounded-memory guarantee. ExportJSON and a retained-storage-only public composition have not been migrated.
